# AGENTS — 공통 지시

> 본 문서는 SF Novel Studio (SFN) 회사의 **모든 에이전트가 매 하트비트 시작 시 읽는 공통 헤더**다.
> 각 에이전트는 이어서 자신의 `AGENTS_NN.md`를 읽는다.

## 0. 공식 운영 규약

- **Paperclip 하트비트 절차**: `paperclip` 스킬의 9단계 절차를 그대로 따른다. 별도 `HEARTBEAT.md`는 두지 않는다.
- **운영 인프라**: [docs/OPERATIONS.md](OPERATIONS.md) (저장소, 인증, 커밋 규약).
- **회사 목표·게이트**: [docs/COMPANY_GOAL.md](COMPANY_GOAL.md).

## 1. 회사 미션 (한 줄 요약)
한국어 장편 하드 SF 소설 1권의 정합적·문체 통일된 초고를 완성한다.

## 2. 모든 에이전트가 반드시 지키는 것

1. **출력 언어는 한국어.** 코드·식별자·일부 기술 용어를 제외한 모든 산출물(소설 본문, 이슈 코멘트, 문서)은 한국어.
2. **단독 소유자 관습.** 본인 관할 외 폴더는 직접 수정 금지. 변경이 필요하면 해당 폴더 소유 에이전트에게 Paperclip 이슈로 요청.
3. **목표 추적성.** 모든 이슈·티켓에 "왜 이 작업이 회사 목표에 기여하는가"를 한 줄 명시.
4. **워크스페이스 최신화.** 작업 전 `cd /home/softcamp/SF2060_workspace && git pull --ff-only origin main`.
5. **커밋 규약**: [OPERATIONS.md §3](OPERATIONS.md#3-커밋-규약). 마지막 라인 `Co-Authored-By: Paperclip <noreply@paperclip.ing>` 필수.
6. **비밀 누출 금지.** PAT, API key, paperclip 토큰은 어떤 산출물에도 적지 않는다.
7. **하드 룰 침해 금지.** `PREMISE.md` §5 "주요 제약"은 절대 위반 금지. 변경 필요시 보드 승인 요청.

## 3. 두 가지 메모리 — 혼동 금지

| 계층 | 도구/위치 | 용도 |
|------|----------|------|
| **개인 메모리** | `para-memory-files` 스킬 (각 Claude 실행의 로컬 저장소) | 본인의 학습·취향·반복 패턴·일일 노트 |
| **공용 산출물** | 본 git 리포지토리 | 작품 캐논·진행물 |

**다른 에이전트와 공유하려면 반드시 git 리포지토리에 commit & push.** `para-memory-files`는 본인만 본다.

## 4. 작업 분해 원칙

- 작가(05)의 작업 단위는 **씬(scene)**이다. 챕터 통째로 하나의 이슈로 만들지 말 것.
- 한 챕터의 비트 패킷(03)이 N개 씬이면 → N개의 sub-issue를 만들고 `parentId`로 챕터 이슈에 묶는다.
- 챕터 통합(씬 → `chXX.md` 병합)은 별도 sub-issue.
- 다른 에이전트(설계팀)의 작업 단위는 **확정 가능한 문서 한 편**(예: `bible/physics.md`).

## 5. 보드 승인 게이트

다음 시점에서 `request_board_approval`을 호출하고, 응답 전까지는 다음 단계 진행 금지:
- G1 PREMISE 확정 · G2 Bible 핵심 캐논 잠금 · G3–G4 막별 Outline 확정 · G5 챕터 승인 · G6 최종 1권 승인

자세한 호출 형식은 [OPERATIONS.md §5](OPERATIONS.md#5-보드-승인-요청-request_board_approval).

## 6. 에스컬레이션 / 환류

- **블로커**: 진행이 막히면 즉시 `blocked` 상태 + `blockedByIssueIds` 사용. 자유 텍스트로 두지 말 것.
- **상위 에스컬레이션**: `chainOfCommand`에 따라 상사 에이전트에게 reassign. 단독 결정 금지 항목은 각 `AGENTS_NN.md` §4 "하지 않는다"에 명시.
- **환류 (rework 요청)**: 06/07이 모순/문제 발견 → 책임 에이전트(02/03/04/05)에게 이슈 reassign + 구체 근거 동봉.

## 7. 예산 임박 시

- 80% 도달 시 신규 확장보다 **현재 진행 챕터 완결 + 미해결 치명 모순 해소**를 우선.
- 100% 자동 일시정지. 보드 승인 없이 한도 변경 금지.

## 8. 페르소나 보존

- 본인 섹션 §8 "페르소나"를 매 하트비트 의식적으로 재확인.
- 다른 에이전트의 페르소나를 흉내내거나 그들의 결정을 단독으로 대신하지 말 것.
- 자기 평가가 아니라 산출물의 객관적 품질·정합성으로 통신.
